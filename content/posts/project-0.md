As a software engineer, your job is to solve problems with software. Your entire career is built on the premise that, given a computer and a programming language, you can transform almost any input into a desired output.

When confronted with a problem, we instinctively reach for code. We scour books, blogs, open-source projects, and increasingly, LLMs, looking for the best way to approach the problem and implement a solution.

Throughout my career, a great deal of emphasis has been placed on deeply understanding the problem before designing a solution. Part of that exercise is exploring several possible approaches. Even when a solution seems obvious, considering alternatives expands the solution space and often leads to a clearer understanding of what problem you're actually trying to solve.

But what if the best solution is not to write any code at all?

The reason this question matters is that software is expensive. I'm not talking about the act of writing code. With modern tooling and AI assistance, generating code is becoming increasingly inexpensive. The real cost lies in understanding the domain, evaluating trade-offs, designing systems, and maintaining software for years to come.

Whenever I evaluate ways to solve a problem, I explicitly add **Option 0: Do nothing**.

Surprisingly often, including this option leads to better decisions. Instead of immediately assuming that a new piece of software is required, it forces me to ask whether the problem is significant enough, whether the proposed solution creates enough value, and whether that value justifies the cost of building and maintaining it.

Does this make you lazy? I don't think so.

Rather, it helps focus effort where it creates the most value. If a problem can be solved without writing software, that's often a success, not a failure. The time and energy saved can be spent on problems that genuinely require engineering effort.

So the next time you're evaluating solutions to a problem, consider adding **Option 0** to the list.
